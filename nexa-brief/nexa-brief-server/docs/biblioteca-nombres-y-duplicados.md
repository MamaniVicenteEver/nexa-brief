# Nombres visibles y duplicados de biblioteca

Cada respuesta de `/api/v1/library/{images|videos|music|sounds}` incluye `display_name`, un nombre visible independiente de `original_filename` y de los campos descriptivos existentes. Los registros anteriores sin ese atributo reciben un valor de lectura a partir de `label`, `track_name`, `title` o `original_filename`, según el tipo. No es necesario reescribir los JSON históricos. La búsqueda también consulta `display_name`.

Para modificarlo, usar `PATCH /api/v1/library/{kind}/{asset_id}` con `{"display_name":"Nombre claro"}`. Se acepta texto no vacío de hasta 240 caracteres. La edición modifica metadata, sin cambiar el nombre del archivo, el identificador, las descripciones de visión ni las referencias. Las restricciones existentes para recursos vinculados a una producción siguen vigentes y responden 409.

En cargas de `images` y `videos`, la biblioteca compara el nombre original, incluyendo extensión, sin distinguir mayúsculas y normalizado Unicode, dentro de la categoría solicitada y del tipo. Si no existe, crea el recurso y responde 201. Si existe y los bytes coinciden (SHA-256), devuelve el recurso existente con 200 y añade, si corresponde, la procedencia de la plantilla. Si el nombre coincide pero el contenido es distinto o el archivo previo no está disponible, responde 409 con un mensaje y conserva el registro y el archivo anteriores. El mismo nombre en categorías distintas puede representar recursos diferentes. Los recursos asociados a producciones no participan en esta comparación. La música y los efectos conservan su deduplicación previa por contenido.

La búsqueda de coincidencia y la inserción se coordinan con `DataStore.coordination("library-upload-image")` o `DataStore.coordination("library-upload-video")`. El adaptador JSON implementa ambos nombres mediante bloqueos entre procesos para el perfil activo; cualquier adaptador futuro debe ofrecer exclusión equivalente para los mismos nombres. La comprobación cubre estas rutas de carga y la garantía depende del cumplimiento del puerto por el adaptador seleccionado. La operación sobre archivo y registro no constituye una transacción distribuida: un fallo después de guardar el archivo pero antes de insertar el registro puede dejar un archivo huérfano, como en el flujo anterior.
